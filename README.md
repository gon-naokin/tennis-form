# テニス フォームチェック

テニス班向けの、サーブ動画の骨格解析アプリです。10〜15 秒の動画を選ぶと、ブラウザの中で骨格を読み取り、肘・膝などの角度を表示します。サーバーは使わず、GitHub Pages だけで動きます。

## できること

- 動画に骨格を重ねて再生（1× / 0.5× / 0.25× / 0.1×、コマ送り）
- 肘の角度、脇の開き、トスの腕の上がり、左右の膝の角度、体の傾き、手首の高さを数値で表示
- フォームのチェック：トロフィーポーズとインパクトの 5 項目を目安と比べ、定型のコメントを表示
- プロの参考値：各項目に、プロ男子・女子の値（中央値と、半数の選手が入る範囲）を並べて表示
- 動画ごとに「サーブの種類（フラット／スライス／スピン）」と「撮った向き（横から／後ろから）」を選択。比較のとき、種類や向きが違えば知らせる
- 打点の位置：頭から前後（横から）・左右（後ろから）にどれだけずれた所で打ったかを表示（良し悪しは決めない参考値）
- 手元の拡大：ラケットを持つ手のまわりを大きく映す。コマ送りでインパクトの瞬間を探し、面の向きを目で確かめる（角度は測らない。スロー撮影向き）
- 面の向きを測る：拡大した絵の上で、面の先端・根元・左右の端の 4 か所をタップすると、面が正面からどれだけ向きを変えているかを出す。面を斜めから見ると細く（見える面積が小さく）なることを使う。面がどちら側を向いているかは分からない
- A と B の違い：2 本並べると、違いの大きい順の一覧と、骨格を重ねた図（足元と体の高さをそろえ、手首どうしを点線で結ぶ）を表示。差が 10°・0.05 倍・5% 以上の項目を「はっきり違う」として目立たせる
- トロフィーポーズとインパクトの瞬間を自動で探してジャンプ（外れたら「いまの位置をインパクトにする」で手動指定）
- 角度の時間変化をグラフ表示（なぞると動画がその位置に移動）
- 2 本の動画を、インパクトの瞬間をそろえて並べて比較

## サーブ以外のショット

動画の下の「ショット」で、サーブ・スマッシュ・フォアハンド・バックハンド・ボレーを選びます。ショットによって、山場の探し方とチェックの項目が変わります。

| ショット | インパクトの探し方 | もう 1 つの場面 | チェックの項目 |
|---|---|---|---|
| サーブ | 手首がいちばん高い瞬間 | トロフィーポーズ（膝が最も曲がった瞬間） | 下の「フォームのチェックの目安」の 5 項目＋打点の位置 |
| スマッシュ | サーブと同じ | サーブと同じ | 反対の腕の上がり、肘の伸び、打点の高さ、打点の位置 |
| フォアハンド・バックハンド | 手首がいちばん速い瞬間 | テイクバック（手をいちばん後ろへ引いた瞬間） | 膝の曲げ（150° 以下）、打点の前後（腰より 10% 以上 前）、肘の角度（参考） |
| ボレー | 同上 | 同上 | テイクバックの大きさ（腰より後ろへ 10% まで）、打点の前後（5% 以上 前）、膝の曲げ（160° 以下） |

- **サーブ以外の目安は仮の値です。** プロのデータがサーブしかないため、一般的な指導内容をもとに置いています。数値は `docs/js/coaching.js` の `STROKE_GUIDE` にまとめてあります。
- **打点の前後・テイクバックの大きさは、真横から撮った動画でだけ測れます。** 手首が腰から、振る向きにどれだけ前にあるかを、体の高さに対する割合で出します。
- **ラリーの動画は何球も見つかります。** 動画の下の「フォアハンド 1」「フォアハンド 2」…から選びます。フォアとバックが混ざった動画では、どの球がどちらかは見分けません。
- **ショットが違う 2 本は比べません。** 「A と B の違い」欄は、同じショットどうしのときだけ出ます。

## フォームのチェックの目安

コメントは、角度が目安から外れたときに決まった文を出す仕組みです（AI による文章生成ではありません）。目安は、下の「プロの参考値」の分布にゆとりを足して決めています。数値と文は `docs/js/coaching.js` の `GUIDE` と `CHECKS` にまとまっているので、班の教え方に合わせて書き換えられます。

| 場面 | 項目 | 目安 | プロの中央値 |
|---|---|---|---|
| トロフィーポーズ | 膝の曲げ（深く曲げた側の膝の角度） | 後ろから 120° 以下／横から 155° 以下 | 後ろから 約 100°／横から 約 145° |
| トロフィーポーズ | トスの腕の上がり | 130° 以上 | 160〜168° |
| インパクト | 肘の伸び | 160° 以上 | 170〜173° |
| インパクト | 打点の高さ（手首の高さ ÷ 鼻の高さ、足首基準） | 1.2 倍以上 | 1.30〜1.32 倍 |
| インパクト | 膝の伸び（伸びている側の膝の角度） | 155° 以上 | 177〜179° |

- **撮った向きを選びます。** 膝の曲げは向きで見え方が大きく変わります。サーブの構えは体が横を向くので、膝は横へ曲がります。後ろから撮ると曲がりがそのまま見え、横（ベースラインの延長）から撮るとカメラの方へ曲がるので浅く見えます。
- **インパクトの 3 項目は、前後 0.1 秒でいちばん大きい値を使います。** 打つ瞬間がコマの間に落ちることがあるためです。
- **「利き腕の肘の高さ」は外しました。** 膝が最も曲がった瞬間のプロの値が、当初の目安（80° 以上）にまったく届かなかったためです。
- **「打点の位置」は判定しません。** 手首が頭から水平にどれだけ離れているかを、体の高さ（足首から鼻まで）に対する割合で出します。横からは前（ネット側）が正、後ろからは利き腕側が正です。プロの中央値は、前へ 13〜16%、利き腕側へ 17〜19% です。選んだ種類に応じて、一般的な傾向（スピンは頭の真上寄り、など）を一言添えます。
- **サーブの種類は利用者が選びます。** 映像からは判別しません。ラケットとボールを見ていないので、回転の種類は分からないためです。
- **プロの参考値は種類別に分けていません。** 元データに種類の記録がなく、代わりにファーストとセカンドで比べましたが、打点の高さ・位置・膝の曲げのどれにも測れるほどの差が出ませんでした（球速は 30km/h 前後違います）。中継映像からの推定では、種類による数 cm の違いは誤差に埋もれます。

## プロの参考値

`docs/data/pro-reference.json` に、プロ男子 50 人・女子 52 人（サーブ計 約 3,850 本）の集計値が入っています。

- 出典：Jason Wang ほか「Large-Scale 3D Pose Estimation of Professional Tennis Serves from Broadcast Video」（CVPR 2026 ワークショップ）の公開データ <https://github.com/jasnwag/tennis_serve_dataset>（CC BY 4.0）。2024 年全米オープンの中継映像から推定された 3D の骨格です。
- 作り方：3D の骨格を「横から」「後ろから」見た形に直し、アプリと同じ計算（`pose-math.js`・`coaching.js`）で各項目を出しています。本数の多い選手に引きずられないよう、選手ごとの中央値を取ってから分布（25%・50%・75%）を出しています。追跡の乱れがないと確認されたサーブ（品質ラベル 3）だけを使っています。
- 入れているのは集計値だけです。選手名や元の骨格データは入れていません。
- 精度の限界：元データは中継映像 1 台分からの推定で、計測器による検証はされていません。手足の長さが 1 本の中で 10〜25% 揺れるなど、誤差は小さくありません。「後ろから」の値は中継カメラの見え方に近く比較的確かで、「横から」の値は奥行きの推定に頼るぶん不確かです。

集計し直す手順（元データは `tennis-ref-data/` など、このリポジトリの外に置きます）：

```
python -I tools/parquet_to_json.py <metadata.parquet> <metadata.json>
node tools/build-pro-reference.mjs --keypoints <keypoints フォルダ> --inspect
node tools/build-pro-reference.mjs --keypoints <keypoints フォルダ> --meta <metadata.json> --out docs/data/pro-reference.json
```

元データの注意：公開ページは関節の並びを COCO と説明していますが、実物は Human3.6M の並びで、高さの軸は上が正でした。

## プライバシー

動画は端末の中だけで処理し、どこにも送信・保存しません。外部から読み込むのは次の 3 つだけです。

- 骨格検出ライブラリ MediaPipe Tasks Vision（cdn.jsdelivr.net、版は `docs/js/app.js` の `MP_VERSION` で固定）
- 骨格モデル `pose_landmarker_full`（storage.googleapis.com）
- 書体 Zen Maru Gothic（Google Fonts）

## ローカルで動かす

```
python -m http.server 8788 --directory tennis-form/docs
```

`http://localhost:8788/` を開きます（`file://` で直接開くと動きません）。

## テスト

角度計算、サーブ検出、フォームのチェックの判定、プロのデータの集計のテストです。

```
node --test tennis-form/tests/pose-math.test.mjs tennis-form/tests/coaching.test.mjs tennis-form/tests/pro-reference.test.mjs tennis-form/tests/compare.test.mjs tennis-form/tests/gate.test.mjs tennis-form/tests/strokes.test.mjs
```

## GitHub Pages で公開する

1. GitHub に新しいリポジトリを作り、この `tennis-form` フォルダの中身を push する
2. リポジトリの Settings → Pages で、Branch を `main`、フォルダを `/docs` にする

## 知っておくこと

- 数値は 1 台のカメラ映像からの推定です。撮る角度で変わるので、同じ条件で撮った動画どうしの比較に使ってください。
- ラケットとボールは検出しません。インパクトは「利き手の手首が最も高い瞬間」、トロフィーポーズは「その直前で膝が最も曲がった瞬間」として探しています。
- 解析は、動画を再生しながら読み取り、取りこぼしたコマだけ後から読み直す 2 段階です。
- 目安はプロの値にゆとりを足したもので、一般の人に合うかどうかは使いながら調整する前提です。

## 見た目

- 配色は指定のパレット（ポラステックブルー `#0088CD`、インディゴ `#332977`、アイス系の背景など）に合わせています。色は `docs/css/style.css` の先頭にまとめてあります。
- 動画 B の色だけは、パレット外の橙（`#EB6834`）を使っています。A の青と確実に見分けられるようにするためで、色覚の違いがあっても区別できることを確認しています。
- 小さい文字のグレーは、パレットのサブグレーより少し濃くしています（白地で読みやすくするため）。
- キャラクターの絵は `docs/img/` にあります。開始画面、解析中の帯、フォームのチェック、A と B の違い、エラー表示、フッターに出ます。結果に応じて絵と一言が変わります。
- 動きを減らす設定の端末では、キャラクターの動きを止めます。

## 入口のパスワード

開いたときにパスワードを聞く画面を付けられます。設定は次のコマンドで行います（パスワードを 2 回入力します）。

```
node tennis-form/tools/set-password.mjs
```

- 書き換わるのは `docs/js/config.js` で、入るのはパスワードそのものではなく照合用の値です。公開（commit・push）すると反映されます。
- パスワードなしに戻すには `node tennis-form/tools/set-password.mjs --clear` を実行します。
- 一度通った端末では、次回から聞かれません。パスワードを変えると、全員がもう一度聞かれます。
- **本当の鍵にはなりません。** 公開されている静的なページなので、中身のファイルは誰でも取得でき、詳しい人は入口を回避できます。URL を知っただけの人がそのまま使えないようにするためのものです。
- 照合用の値は公開されるので、短いパスワードや他で使っているパスワードは避けてください。
